# UV Migration — Design

## 1. Dependency manager swap

Replace Poetry with uv as the project's dependency manager.

- **Delete** `poetry.lock` (generated by Poetry 2.4.1).
- **Generate** `uv.lock` by running `uv lock` and commit it.
- **`pyproject.toml`**: unchanged. The existing `[project]` (PEP 621) and
  `[dependency-groups] dev` (PEP 735) tables are natively supported by uv.
  uv installs all dependency groups by default, which matches the current
  `poetry install --with dev` behavior.
- **`.gitignore`**: unchanged — `.venv/` is already ignored.

## 2. CI workflow — `.github/workflows/ci.yml`

Replace Poetry setup with uv setup.

| Before | After |
|--------|-------|
| `pipx install poetry` | — (removed) |
| `actions/setup-python@v5` with `cache: poetry` | `astral-sh/setup-uv@v6` with `enable-cache: true` and `python-version: ${{ matrix.python-version }}` |
| `poetry install --with dev` | `uv sync --frozen` |
| `poetry run ruff check .` | `uv run ruff check .` |
| `poetry run mypy engagedin` | `uv run mypy engagedin` |
| `poetry run pytest --cov=engagedin --cov-fail-under=100 -q` | `uv run pytest --cov=engagedin --cov-fail-under=100 -q` |

The Python version matrix (`3.12`, `3.13`, `3.14`) is preserved.

## 3. Publish workflow — `.github/workflows/publish.yml`

| Before | After |
|--------|-------|
| `pipx install poetry` | — (removed) |
| `actions/setup-python@v5` (3.12) | `astral-sh/setup-uv@v6` with `python-version: 3.12` |
| `poetry build` | `uv build` |

Trusted publishing via `pypa/gh-action-pypi-publish@release/v1` is unchanged.

## 4. Documentation updates

Files that reference `poetry` and their changes:

| File | Change |
|------|--------|
| `README.md` | Installation: `pip install poetry` → `pip install uv`, `poetry install` → `uv sync`. Development: `poetry install --with dev` → `uv sync`, and the three `poetry run ...` commands → `uv run ...`. |
| `.opencode/agents/test.md` | `poetry run pytest` → `uv run pytest` (all occurrences). |
| `.opencode/agents/code-review.md` | `poetry run ruff check .` → `uv run ruff check .`, `poetry run ruff check --fix .` → `uv run ruff check --fix .`, `poetry run pytest --cov=engagedin` → `uv run pytest --cov=engagedin`. |
| `.opencode/skills/ruff-style/SKILL.md` | The three `poetry run ruff ...` commands → `uv run ruff ...`. |
| `.opencode/skills/testing-conventions/SKILL.md` | The four `poetry run pytest ...` commands → `uv run pytest ...`. |

## 5. Verification

No unit tests are required — this is a tooling migration. Verification is the
existing quality suite run through uv:

```bash
uv sync --frozen
uv run ruff check .
uv run mypy engagedin
uv run pytest --cov=engagedin --cov-fail-under=100
```

Manual checks:

- `uv run engagedin --help` prints the CLI help.
- `grep -ri "poetry" . --exclude-dir=.git` returns no matches.
- A pull request against `main` passes CI on all three Python versions.

## 6. ADR references

None. This migration introduces no architectural decision beyond the dependency
manager swap described above.
